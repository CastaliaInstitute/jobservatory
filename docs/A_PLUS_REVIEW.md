## Publication blockers (P0)

1. Complete the prepared independent evaluation. Two distinct reviewers must label each of 400 blind retrieval pairs and 200 blind hierarchical-classification records; a distinct adjudicator must resolve every disagreement. The machine gate currently and correctly reports all submissions missing.
2. Evaluate the frozen recall-guarded candidate once against the adjudicated temporal set. The strict source-publication split has 616 pre-cutoff candidates and 269 held-out candidates after quarantining nine crossing families, with zero posting-family leakage. It is a source-publication holdout from one snapshot, not longitudinal observation history. Development quality now passes, but promotion must remain blocked until independent evidence confirms the result.
3. Replace weak supervision with independently adjudicated gold labels, validate calibration against those labels, add occupation/source/geography slices, and promote a classifier only if it clears the existing hierarchy, abstention, and tail-label gates.
4. Complete source rights review. Record terms URL, review date, permitted retention, excerpt rule, redistribution, and training permission per source.
5. Accumulate at least 30 stable daily frames before publishing trend signals, and longer before forecasting. Backtest every forecast target.
6. Human-review occupation and software mappings, expand the O*NET profile beyond six occupations, and report mapping precision/coverage on adjudicated data.
7. Make deployment automatic and observable. The scheduled GitHub refresh currently commits data but does not prove that the direct-upload Cloudflare Pages deployment changed.

## High-priority engineering (P1)

- Store HTTP status, ETag/Last-Modified, response hash, latency, and feed schema version in retrieval manifests.
- Validate candidate repost clusters with independently reviewed pairs and content similarity; current normalized employer/title/location families carry explicit confidence but do not claim requisition identity.
- Extend the published JSON Schema contracts to snapshots and every baseline metric artifact; keep strict validation in CI.
- Add hand-built source fixtures for HTML cleaning, compensation units, title relevance, evidence selection, and ontology regressions.
- Run ML evaluation in CI and fail on missing qrels, metric calculation errors, unexplained large regressions, or test-set mutation.
- Configure durable Workers Logs/metrics retention and SLO alerts, then run a distributed load test before making global latency or capacity claims.
- Finish WCAG testing with axe/Playwright checks and a manual screen-reader/mobile audit; focus trapping/restoration, semantic table roles, and visible mobile navigation are implemented.
- Add a data dictionary, repository/content license, citation file, release checksums, and changelog.

## Technical Fellow evidence bar

The defensible CV bullet today can include a provenance-aware 2,700+ record public corpus from 53 Greenhouse/Lever/Ashby feeds across 37 declared sectors; explicit coverage targets and gaps; durable version/analysis lineage; structured compensation provenance; a content-addressed BM25 Pages Function with model/index/corpus contracts, fail-closed SHA verification, cache and timing telemetry; and a reproducible semantic-retrieval/cross-encoder experiment with explicit rejection gates. The bounded single-client benchmark supports its exact latency figures, not a global SLO. It is still not defensible to claim production semantic retrieval, superior cross-encoder reranking, extreme multi-label classification, validated calibration, market trends, forecasting, or labor-market representativeness.

The application-ready bar is reached only when the P0 items are completed and a clean checkout reproduces the held-out metrics and latency report. The current ML result is bounded but useful: generic MiniLM embeddings substantially underperform BM25, unrestricted cross-encoder reranking trades better MRR/nDCG for worse recall, and the recall-guarded candidate clears only the development quality gate. Independent temporal evidence—not development-set architecture work—is now the decisive retrieval blocker.

The public release ledger currently passes 5/13 gates: source-universe completeness, static delivery, scoped counterfactual testing, automated accessibility, and versioned baseline serving. It deliberately remains `blocked`; a checklist entry cannot pass without its evidence artifact and manual assurance where required.
